## תקציר
CircuitMaker היא אפליקציית Web חינמית לבנייה, הרצה והדמיה ויזואלית ותנועתית של מעגלים ספרתיים. היא מיועדת בעיקר לסטודנטים בקורס "מבוא לחומרה" ובקורסי יסוד דומים.

ארבעה רכיבים עיקריים:
- **(א) משטח עבודה** ויזואלי עם Drag-and-Drop וספריית רכיבים לפי סילבוס הקורס: שערים, MUX, מפענחים, מקודדים, מסכמים, latches, flip-flops, אוגרים ומונים. זרימת האותות מוצגת בתנועה, עם הבחנה ברורה בין 1 ל-0.
- **(ב) מנוע סימולציה מבוסס אירועים** שמתזמן כל שינוי אות לפי ההשהיה של כל שער, ולכן משחזר glitches ו-hazards.
- **(ג) דיאגרמת זמנים** בתחתית המסך, עם צורות הגל של האותות הנבחרים.
- **(ד) מודול ניתוח לימודי** שמזהה hazards סטטיים ודינמיים, מסביר את המקור הלוגי שלהם ומציע תיקון.

המימוש ב-TypeScript ו-React. הכול רץ בצד הלקוח, בלי שרת אפליקטיבי ובלי התקנה. Vite משמש ככלי הבנייה וכשרת הפיתוח המקומי, והקבצים הסטטיים שהוא מפיק מפורסמים ב-GitHub Pages. הנתונים נשמרים בדפדפן ובקובצי JSON אצל הסטודנט.

## מוטיבציה
- הקושי המרכזי בקורס הוא **למידה סטטית של תהליכים דינמיים**: לומדים משרטוטים קפואים, ובשאלות על השהיות ועל רכיבים מורכבים צריך לדמיין בראש מה קורה לאורך זמן.
- **השוואה לכלים קיימים:**
  - Logisim / Logisim-evolution: ממשק מיושן, דורש Java, לא ממחיש השהיה לכל שער וריצודים בזמן אמת.
  - iCircuit: בתשלום ולא מותאם לקורס.
  - CircuitVerse ודומיו: לא מתמקדים בהתפשטות אותות לפי השהיה, ואין בהם ניתוח לימודי של hazards.
  - ModelSim / Vivado: דורשים כתיבת קוד ולימוד כלי תעשייתי.
- **התרומה:** כלי חינמי אחד בדפדפן שמשלב מודל השהיות לכל שער, הדמיה תנועתית, דיאגרמות זמנים מסונכרנות וניתוח אוטומטי. "למידה דינמית של תהליכים דינמיים".
- **חלופות מימוש:** (1) הרחבת Logisim-evolution (Java); (2) אפליקציית דסקטופ ב-Python + PyQt; **(3) נבחרה: Web בצד הלקוח (TypeScript + React).** את המנוע צריך לכתוב בעצמנו, וזה מכוון, כי הוא לב הפרויקט.
- סימולציית zero-delay נשקלה ונדחתה, כי היא לא יכולה להציג ריצודים.

## רקע תיאורטי ומקורות
אלגברה בוליאנית, מפות קרנו ו-Quine-McCluskey (למרות שירד מסילבוס 2026), רכיבים צירופיים, propagation delay ומודל transport, hazards סטטיים ודינמיים ותיקון בעזרת מונח קונצנזוס, סימולציה מבוססת אירועים (תור אירועים, delta cycles כמו ב-Verilog/VHDL), ורכיבים עקיבים.
- Langholz, Kandel, Mott — Foundation of Digital Logic Design (1998, reprint 2011).
- Even & Medina — Digital Logic Design: A Rigorous Approach (2016). גרסה חינמית: hyde.eng.tau.ac.il/Even-Medina/node1.html
- שקפי והרצאות "מבוא לחומרה", ד"ר יונתן אוסטרומצקי.

## דרישות המערכת
- **פונקציונליות:**
  - הוספה, הזזה, מחיקה וחיווט של רכיבים בגרירה.
  - כניסות שאפשר להחליף (מתג, שעון) ויציאות.
  - רכיבים צירופיים: שערים, MUX, מפענח, מקודד, חצי מסכם ומסכם מלא.
  - רכיבים עקיבים: SR latch, D latch, D/T/JK flip-flop, אוגר ומונה של 4 ביט.
  - השהיה לכל שער.
  - הרצה, עצירה וצעד-אחר-צעד, עם בקרת מהירות.
  - צביעה ואנימציה של 1/0/X.
  - דיאגרמת זמנים.
  - התרעה והסבר על hazards.
  - שמירה אוטומטית בדפדפן, ייצוא וייבוא ב-JSON, וספריית מעגלי דוגמה מהקורס.
- **לא-פונקציונליות:** רץ בדפדפנים נפוצים בלי התקנה, אנימציה של כ-60 FPS עד 200 רכיבים, ממשק בעברית (אנגלית כהרחבה), קוד פתוח ופריסה חינמית.

## שלבים ושיטות מימוש
- **מודל נתונים:** netlist של רכיבים, פורטים וחוטים. כל חוט נושא ביט יחיד, לכל רכיב יש השהיה, והשמירה ב-JSON.
- **משטח עבודה:** React Flow, או SVG/Canvas ייעודי.
- **מנוע:**
  - תור עדיפויות לפי זמן. כשכניסה משתנה, השער מחושב מחדש והיציאה מתוזמנת ל-t+d.
  - מודל transport, ביחידות ns.
  - תמיכה במשוב (latch) ובשעון, וזיהוי תנודות.
- **אנימציה:** זמן הסימולציה ממופה לזמן אמת לפי מקדם מהירות, ו"פולס" נע לאורך החוט בזמן ההשהיה.
- **דיאגרמת זמנים:** היסטוריית אותות ב-SVG/Canvas, עם סמן זמן ומדידת משך הריצוד.
- **מודול ניתוח:**
  - (1) אנליטי: ביטוי בוליאני → מונחים סמוכים שלא מכוסים במונח משותף (static-1) → הצעת מונח קונצנזוס. למעגלים דו-רמתיים.
  - (2) סימולטיבי: מריצים את כל מעברי הכניסה הבודדת, ובודקים אם יש יותר ממעבר אחד ביציאה (hazard סטטי או דינמי). התוצאה מוצגת כטקסט מסביר, עם הדגשת הנתיבים האחראים.

## ארכיטקטורת פריסה ושמירת נתונים (נוסף בגרסה המתוקנת)
- **תפקיד Vite:**
  - בפיתוח: שרת פיתוח מקומי עם HMR.
  - בבנייה: `vite build` מפיק קבצים סטטיים ב-`dist/`. `vite preview` רק לבדיקה מקומית, לא שרת ייצור.
  - אחרי העלייה: GitHub Actions מריץ בדיקות ובנייה ומעלה את `dist/` ל-GitHub Pages (חלופה: Vercel). באתר המפורסם Vite לא רץ.
- **למה אין שרת אפליקטיבי:** כל החישוב בדפדפן. אין חשבונות, אין נתונים משותפים ואין סודות. היתרונות: אחסון חינמי, בלי תחזוקה ואבטחה של שרת, תגובה מיידית, ועבודה גם בלי רשת אחרי הטעינה.
- **שמירה מקומית:**
  - המעגל הנוכחי → IndexedDB (שמירה אוטומטית).
  - מעגלים לשמירה ולשיתוף → קובץ JSON (ייצוא וייבוא דרך File API).
  - העדפות → localStorage.
  - מעגלי דוגמה → JSON סטטי בתוך האתר.
- **מגבלות ומענה:**
  - נתוני דפדפן יכולים להימחק → ייצוא JSON הוא השמירה הקבועה, עם תזכורת בממשק.
  - אין סנכרון בין מכשירים → העברת קובץ; BaaS כהרחבה עתידית, מחוץ לתכולה.
  - נפח: עשרות KB למעגל, זניח.
  - אין נתוני שימוש בשרת → שאלון שמישות.
- **אימות:** באבן דרך 3 מקימים שלד Vite וצינור פריסה, ומוודאים שהקוד מתנהג זהה בשרת הפיתוח ובאתר המפורסם (base, IndexedDB, JSON).

VS Code, Node.js, TypeScript; Figma (wireframes); React, React Flow, SVG, Zustand, i18next, Vite; המנוע בלי ספריות חיצוניות (Min-Heap), Web Worker כהרחבה; requestAnimationFrame ו-SVG/CSS לאנימציה; HTML Canvas או SVG לדיאגרמת זמנים; Quine-McCluskey ומונחי קונצנזוס במימוש עצמי, עם תבניות טקסט בעברית; Vitest, Playwright, Icarus Verilog + GTKWave (מעגלי בדיקה ב-Verilog עם השהיות); Git, GitHub, GitHub Actions, GitHub Pages או Vercel.

## תוצרים
- **עד דו"ח המעקב:**
  - אפיון דרישות ו-wireframes.
  - אב-טיפוס פרוס עם שערים בסיסיים (AND, OR, NOT, NAND, NOR, XOR), חיווט, כניסות ויציאות, וסימולציה לוגית עם צביעת 1/0/X.
  - ספרייה מורחבת: MUX, מפענח, מקודד, HA/FA, SR/D latch, D-FF, שעון, אוגר ומונה של 4 ביט, ושמירה וטעינה.
  - גרסה ראשונה של מנוע ההשהיות, עם בדיקות יחידה מול חישוב ידני.
- **בסוף הפרויקט:**
  - האפליקציה המלאה (א–ד) בכתובת ציבורית ובקוד פתוח.
  - ספריית מעגלי דוגמה מהקורס, כולל hazards ידועים, ומדריך משתמש.
  - דו"ח סופי, פוסטר ותיעוד טכני.
- **ההדגמה בבחינת הפרויקט:**
  - MUX 2:1 משערים עם השהיות שונות בענפים. מחליפים את כניסת הבחירה, ורואים את הפולס, את הריצוד בהדמיה ובדיאגרמת הזמנים, ואת ההתרעה על static-1 עם הצעת מונח קונצנזוס. אחרי ההוספה הריצוד נעלם.
  - בנוסף: מסכם ripple-carry ומונה 4 ביט שמונע משעון.

## שיטות בדיקה
- Vitest: טבלאות אמת, התנהגות latch, FF, אוגר ומונה, ותזמון אירועים מול חישוב ידני.
- השוואה ל-Icarus Verilog על אותם מעגלים עם השהיות.
- מודול הניתוח: סט מעגלים עם hazards ידועים, ומדידת שיעור הזיהוי הנכון ושיעור ההתרעות השגויות.
- Playwright: תרחישים מקצה לקצה, קצב פריימים ותאימות דפדפנים.
- שמישות: 5–10 סטודנטים פותרים שאלות עם הכלי וממלאים שאלון.
